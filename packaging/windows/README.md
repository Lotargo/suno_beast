# Сборка Windows-установщика

Готовый комплект работает без системных Node.js, npm, FFmpeg и ffprobe. Установка не выполняет сетевых загрузок, не меняет системный PATH и использует HKCU. Расширение подключается вручную через режим разработчика браузера.

## Сборка

На машине сборки нужны Windows x64, PowerShell, Git, WSL с Ubuntu, `bash`, `make`, `tar`, `xz` и `pkg-config`. Пакеты приложения в npm не нужны. Требования относятся только к сборке, не к конечному пользователю.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-windows-installer.ps1
node tools/test-windows-installer.js
```

Первая сборка загружает зафиксированные в `dependencies.json` архивы по HTTPS и проверяет SHA256. Inno Setup разворачивается в переносном режиме в `.cache/windows-installer/inno`; можно передать `-IsccPath` к собственному компилятору. Использование компилятора регулируется лицензией выбранной версии Inno Setup.

FFmpeg и ffprobe собираются из FFmpeg 8.1.3, LAME 4.0 и zlib 1.3.2 через LLVM-MinGW. GPL и nonfree-компоненты отключены, доступ к сети в FFmpeg отключён. Включены декодирование WebM/Opus и MP3, кодирование MP3/WAV, обработка обложек PNG/JPEG/WebP и используемые приложением аудиофильтры. Точные исходные архивы, сценарий сборки, параметры и лицензии входят в установленную папку `licenses`. Источники не изменяются.

Node.js 24.22.0 LTS берётся из официального Windows x64-архива. В комплект копируются `node.exe` и полный файл лицензий; npm не копируется. `runtime-info.json` фиксирует версии, источники и контрольные суммы компонентов.

Результат: `dist/Suno-Beast-v<version>-Windows-x64-Setup.exe`. Бинарные файлы, кеш сборки и тестовые журналы исключены из Git. Текущая сборка не подписана сертификатом издателя. При наличии сертификата установщик можно подписать перед публикацией.

## Проверка установщика

`tools/test-windows-installer.js` запускает настоящий Setup в отдельной папке с кириллицей и пробелами. Все дочерние процессы получают PATH только с Windows System32. Регистрация изолирована в `HKCU\Software\SunoBeastInstallerTests\<UUID>`, состояния и записи — в отдельной временной папке. Действующие браузерные регистрации не меняются.

Проверяются автоматическое переключение прежней и устаревшей регистрации, откат при сбое между записями ключей Chrome/Edge, защита непустой папки и границ тестовой регистрации, установка без внешних инструментов, запуск Native Messaging, MP3/WAV, теги, обрезка тишины, обложка, дубли, восстановление повреждённой записи, повторная установка и отсутствие отката на системный FFmpeg. Удаление проверяется с восстановлением существующего прежнего помощника, пропуском устаревшего пути, сохранением более поздней регистрации и пользовательских файлов. Синтетический WebM/Opus лежит в `tests/fixtures/installer-tone.webm`.

Отчёт: `dist/windows-installer-validation.json`. Исходные журналы остаются во временной QA-папке для диагностики. Это проверка установленного помощника и установщика; она не заменяет запись реального трека через расширение в каждом браузере.

Параметр `/SBTESTID=<32 hex>` изолирует тестовый AppId и регистрацию. Только в таком режиме `/SBTESTFAIL=after-first-registration` воспроизводит сбой между записями двух регистраций для проверки отката, а `/SBTESTFAIL=missing-component` — отсутствие FFmpeg при предварительной проверке. Обычная установка без этих параметров использует постоянный AppId и пользовательские ключи Chrome/Edge. Opera/GX и Яндекс на Windows используют регистрацию Chrome.

## Обновление и удаление

Перед обновлением и удалением заверши запись и закрой браузеры с Suno Beast: открытое соединение с помощником удерживает его исполняемый файл. Обновление разрешено в существующую папку, созданную этим установщиком. Папка с `.git`, посторонние непустые папки и установки с другой тестовой областью блокируются до копирования.

После проверки встроенных компонентов установщик сохраняет предыдущие пути Chrome/Edge в `registration-backup.ini` и переключает только регистрацию `com.sunobeast.audio`. Если запись регистрации не удалась, прежние значения восстанавливаются. Повторная установка сохраняет первоначальную резервную копию, пока регистрация указывает на эту установку. Старые папки и их содержимое не меняются. После переключения перезапусти браузер, чтобы он подключил нового помощника.

При удалении обрабатываются только значения Native Messaging, всё ещё указывающие на эту копию: прежний путь восстанавливается, если его файл существует, иначе значение удаляется. Регистрация, переключённая после установки на другую копию, сохраняется. Убираются только зарегистрированные программные файлы; пользовательский `%LOCALAPPDATA%\SunoBeast`, записи, браузерные профили и посторонние файлы не удаляются.
