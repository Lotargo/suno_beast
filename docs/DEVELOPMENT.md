# Разработка Suno Beast

## Структура

| Каталог | Назначение |
| --- | --- |
| `extension/` | Готовое расширение Manifest V3: панель, телеметрия Suno, запись и загрузки |
| `native/` | Node.js-помощник, FFmpeg, индекс коллекции и регистрация Native Messaging |
| `tests/` | Проверки записи, метаданных, файлов и границ доступа |
| `tools/` | Предпросмотр интерфейса и генерация иконок |
| `docs/images/` | Баннер и скриншоты README |

## Проверки

```powershell
npm test
```

Нужны Node.js, FFmpeg и ffprobe; установка npm-пакетов не требуется. Тесты моделируют API Chrome и проверяют переходы рекордера, задержки обработки, неполные треки, дубли, Native Messaging, теги, обложки, загрузки, метаданные и RU/EN. Тест сгенерированного Windows-лаунчера пропускается на других платформах и если установщик ещё не создавал его. POSIX-тест запуска macOS-лаунчера пропускается на Windows; тест macOS-ветки выбора папки использует подставной `osascript` и выполняется только на macOS. Эти проверки не заменяют проверку системных диалогов и подключения браузера на реальном Mac.

Для проверки установленного расширения включи Auto-Grab до начала трека, дождись завершения двух треков, а третий прерви в Suno. Первые два должны сохраниться целиком, третий — отсутствовать в загрузках. Системные диалоги и доставку в реальные загрузки проверяй в браузере.

## Предпросмотр интерфейса

```powershell
node tools/preview-popup.js
```

- `http://127.0.0.1:18889/popup.html` — панель.
- `http://127.0.0.1:18889/floating-preview.html` — панель поверх демонстрационной страницы.
- `http://127.0.0.1:18889/docs-showcase.html` — три экрана для скриншотов README.

Это демонстрационные данные: предпросмотр не записывает звук и не подключает помощник. Варианты панели задаются `?state=recording`, `album`, `empty`, `duplicate`, `error`, `long`. Для документации используются `?docs=recording`, `metadata`, `settings`: фиксированный таймер, локальная обложка и пример текста. Разрешение локальной обложки действует только в предпросмотре.

Баннер хранится как редактируемый SVG. Скриншоты снимаются с настоящего `popup.html`; данные и обложка примера находятся в инструменте предпросмотра и `tools/fixtures/`.

## Иконки

`tools/render-icons.js` пересобирает PNG из `extension/assets/suno-beast-icon.svg`. Только этому инструменту нужен внешний модуль `sharp`; путь к модулю можно передать через `SUNO_BEAST_SHARP`. Готовые PNG уже включены в репозиторий.

## Локальные файлы

- `npm run install:helper` запускает `native/install.js`: на Windows он вызывает `native/install.ps1`, на macOS регистрирует помощник в пользовательских папках Native Messaging для Chrome, Edge и Яндекс Браузера. Opera и Opera GX используют регистрацию Chrome; Яндекс Браузер на Windows также читает регистрацию Chrome. Linux не поддерживается.
- На Windows установщик создаёт `native/launch-host.cmd` и `native/com.sunobeast.audio.json`, затем регистрирует их в `HKCU:\Software\{Google\Chrome,Microsoft\Edge}\NativeMessagingHosts\com.sunobeast.audio`; на macOS — исполняемый `native/launch-host.sh` и манифесты в подкаталогах `NativeMessagingHosts` внутри `~/Library/Application Support/{Google/Chrome,Microsoft Edge,Yandex/YandexBrowser}`. Лаунчеры содержат пути текущего компьютера и исключены из Git.
- Windows-тест установки и удаления использует отдельный ключ `HKCU:\Software\SunoBeastInstallTests\<UUID>` через параметр `-RegistryRoot`; действующие регистрации браузеров не меняются. Удаление помощника сохраняет регистрации другой копии проекта.
- На macOS в лаунчере сохраняются абсолютный путь к Node.js и каталоги FFmpeg/ffprobe в `PATH`, чтобы помощник работал при запуске браузера из Finder. После переноса проекта или инструментов нужно повторить установку.
- Настройки, индекс коллекции и временные готовые файлы находятся в `%LOCALAPPDATA%\SunoBeast` на Windows или `~/Library/Application Support/SunoBeast` на macOS. Готовые файлы для доставки браузеру находятся в подкаталоге `pending`.
- При ошибке FFmpeg исходник сохраняется как `Recovery_*.webm` в выбранной папке либо в подкаталоге `recovery` каталога состояния.
- При потере связи с помощником расширение пытается сохранить резервный WebM через загрузки браузера в подкаталог `Suno Beast`.
- Лимит исходной записи и очереди — 256 МБ, передача готового файла браузеру ограничена 512 МБ.

`.gitignore` исключает личные записи, зависимости, ключи, сгенерированные файлы помощника и временные предпросмотры `design/`. Небольшие намеренные аудиофикстуры можно хранить в `tests/fixtures/`. Правила переводов строк заданы в `.gitattributes`.

## Границы доступа

Контентный скрипт работает только на `https://suno.com` и `https://www.suno.com`. Дополнительные домены Suno CDN используются для аудио и обложек.

`tabCapture` получает звук вкладки после действия пользователя; `offscreen` поддерживает запись при закрытой панели. `scripting` восстанавливает связь с проверенной вкладкой Suno. `nativeMessaging` передаёт аудио помощнику, `downloads` доставляет готовые файлы, `storage` хранит настройки, `webRequest` обнаруживает аудиопоток.

Панель изолирована iframe расширения и закрытым Shadow DOM. Команды привязаны к сессии панели, вкладке, frame и document. Помощник проверяет origin расширения, команды и размеры данных; загрузчики проверяют каждый redirect CDN. Для чтения входного аудио FFmpeg разрешены локальные протоколы `file,pipe`.

## Проверки совместимости браузеров

Статусы платформ и сценарии для новых браузеров перечислены в [матрице совместимости](BROWSER_COMPATIBILITY.md).

### Яндекс Браузер на Windows — 2026-10-19

Автоматическая проверка выполнена в Яндекс Браузере **26.8.5.811** (Chromium **150.0.7871.811**) с отдельным временным профилем в headless-режиме:

- Пакет `extension/` загружен через DevTools Protocol, страница расширения открылась с ожидаемым ID.
- `tabCapture.getMediaStreamId`, `offscreen.createDocument`, `runtime.getContexts` и `runtime.connectNative` доступны.
- Создан и закрыт настоящий `OFFSCREEN_DOCUMENT` с причинами `USER_MEDIA` / `BLOBS`.
- Из расширения получен ответ `status` от `native/host.js` через временную Chrome-регистрацию с отдельным именем хоста и изолированным каталогом состояния.
- Тестовые ключи `Software\Yandex` и `Software\Yandex\YandexBrowser` дали `Specified native messaging host not found`; в установщике они не используются.

Автоматическая проверка охватывает загрузку, API и транспорт. Работа расширения также проверена вручную в обычном Яндекс Браузере на Windows. Подробный протокол отдельных сценариев, версия браузера и путь к расширению для ручной проверки не зафиксированы.

Opera, Opera GX и Яндекс Браузер на macOS требуют отдельных проверок. Локальные тесты API Chrome и установщика не заменяют проверку записи и доставки файлов в каждом браузере.
